# 客户版与内部版导出补齐订单号和下单时间

## 背景

当前客户版和内部版导出中的订单字段不统一：部分工作表已有“订单”栏，部分工作表使用“系统订单号”或没有订单栏；主表中的“订单”值还可能是旧的批次或日期标识。用户需要在导出的每条明细中直接看到系统正式订单号和下单时间。

## 已确认规则

1. 已有“订单”栏的工作表保留该栏及原位置，不删除、不重复新增。
2. 没有“订单”栏的相关工作表新增“订单”栏。
3. “订单”栏统一填写系统正式订单号，例如 `ZP-00005-CPLY`。
4. 客户版和内部版的相关工作表统一新增“下单时间”栏。
5. 历史数据没有绑定正式订单时，对应订单号和下单时间留空，不猜测、不按款式强行匹配。
6. 不改变现有数量、发货明细、快递单号、SKU、客户 SKU 等字段的计算与内容。

## 影响范围

### 客户版

- `客户发货明细`：保留“订单”栏，改为正式订单号；新增“下单时间”。
- `未发货明细`：同上。
- `发货明细`：已有系统订单信息时统一栏名为“订单”，并保留/补充“下单时间”。

### 内部版

- `订单发货明细`：保留“订单”栏，改为正式订单号；新增“下单时间”。
- `未发货明细`：同上。
- `发货流水`：已有系统订单信息时统一栏名为“订单”，并保留/补充“下单时间”。

公司级导出、全部公司导出、每日发货导出和员工发货导出共用上述工作表生成函数，因此同步遵循相同字段规则。

## 数据来源

- 订单号：优先取发货尺码行绑定的 `OrderLine.order -> SalesOrder.system_order_no`；订单余额主表取订单行绑定的正式订单。
- 下单时间：取同一正式订单的 `SalesOrder.order_date`。
- 若发货单自身绑定了正式订单而尺码行未绑定，则使用发货单的正式订单。
- 两者均无正式订单绑定时留空。

## 实现边界

- 扩充订单余额查询结果，使每行包含正式订单号和正式下单时间。
- 调整客户版与内部版工作表表头和行数据映射。
- 保持原有“订单”栏的位置；“下单时间”紧邻“订单”栏放置，便于查看。
- 不修改数据库结构，不回填历史绑定，不改变网页页面。

## 测试与验收

1. 先增加失败测试，分别覆盖客户版和内部版。
2. 验证已有“订单”栏没有重复，且值为系统正式订单号。
3. 验证所有目标工作表都有“下单时间”。
4. 验证未绑定正式订单的记录两栏均为空。
5. 运行导出相关测试及全量测试。
6. 生成客户版和内部版样本，读取工作簿检查表头和代表性数据行。

## 不在本次范围

- 客户订单号展示规则调整。
- 历史发货与正式订单的新增绑定。
- 导出样式整体改版。
- 腾讯云部署；实现与验证完成后单独按用户指令决定是否上线。
