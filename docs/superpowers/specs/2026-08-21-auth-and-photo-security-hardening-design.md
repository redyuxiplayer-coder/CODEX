# 登录与图片访问安全加固设计

## 目标

修复两类高风险问题，同时保持老板端和员工端现有操作流程不变：

1. 浏览器当前把用户数据库 ID 直接写入 Cookie，任何人都能修改该值冒充其他用户或管理员；
2. 作业信息表单信任浏览器回传的 `photo_path`，图片接口也缺少完整的文件目录和对象所有权校验，可能读取不属于当前用户的图片，甚至读取服务器上的其他文件。

本次只做身份会话和图片访问边界加固，不调整订单、发货、SKU、条形码或页面布局。

## 方案选择

### 身份会话

考虑过三种方案：

1. 数据库会话表：可逐个撤销会话，但需要新增表、清理任务和更多部署步骤；
2. 随机令牌写入用户表：实现简单，但只能保留一个设备会话；
3. HMAC 签名 Cookie：不新增数据库结构，能阻止篡改，适合当前单体服务。

采用第 3 种。服务端使用环境变量中的随机密钥签发带版本、用户 ID 和签发时间的 Cookie；浏览器不能自行构造或修改有效身份。密钥不进入 Git、日志或 Obsidian。

### 图片路径

考虑过继续保存绝对路径并只做前缀字符串判断、改为数据库 Blob、以及保留文件存储但统一做规范化目录校验。采用第三种：改动范围小，并能正确防御 `..`、软链接和伪造绝对路径。

## 签名会话设计

### 令牌格式与验证

- 新增统一的签发和解析函数，页面登录与 API 登录共同调用；
- 令牌包含版本、用户 ID、签发时间，并使用 HMAC-SHA256 签名；
- 所有比较使用恒定时间比较；
- 默认有效期 7 天；过期、格式错误、签名错误、用户不存在或用户停用时均视为未登录；
- 旧的纯数字 Cookie 一律失效，因此上线后所有用户需要重新登录一次；
- 退出登录继续删除 Cookie。

### Cookie 属性

- `HttpOnly=true`；
- `SameSite=Lax`；
- `Path=/`；
- `Max-Age=7天`；
- `Secure` 由部署环境配置：HTTPS 环境开启，本地 HTTP 测试关闭。

### 密钥管理与启动保护

- 环境变量使用 `ZY_SESSION_SECRET`；
- 生产部署时生成至少 32 字节的随机值，写入仅服务账号可读的服务器环境文件；
- 生产环境缺少密钥时应用拒绝启动，不能回退到固定默认密钥；
- 测试通过测试环境变量提供固定测试密钥；
- 轮换密钥会使现有会话全部失效，这是预期行为。

## 图片访问设计

### 可信文件范围

新增统一文件校验函数：

1. 对数据库路径执行绝对化和 `resolve`；
2. 仅允许位于系统管理的上传目录和缩略图目录内；
3. 拒绝目录本身、目录外路径、软链接逃逸、不存在文件和非普通文件；
4. 原图通过校验后才允许生成缩略图；缩略图也必须落在缩略图目录；
5. 校验失败统一返回 404 或原页面，不向用户暴露服务器真实路径。

现有数据库中的合法图片先做只读盘点。若发现历史图片位于旧的合法业务目录，则把该明确目录加入允许列表；不允许用项目根目录或任意父目录作为宽泛白名单。

### 不再信任表单中的路径

- 管理员保存作业信息、员工提交作业信息建议、对应 API 都不再直接采用 `existing_photo_path`；
- 保留图片时，服务端根据“公司 + 产品 + 款式 + 区块标识”从数据库读取原图片；
- 删除图片时只接受删除标记；
- 上传新图片时只采用 `save_uploads` 返回的服务端路径；
- 自定义区块必须使用稳定的区块标识匹配旧记录，不能按浏览器提交的任意路径匹配；
- 建议批准前再次校验建议中保存的图片路径仍属于受管目录。

### 对象权限

- 正式作业信息图片是同一业务团队的共享资料：任意已登录用户可查看；
- 作业信息建议图片：管理员或该建议的提交员工可查看，其他员工返回 404/跳转；
- 发货照片继续保持管理员或该发货记录提交人可查看；
- 草稿照片继续保持管理员或草稿所有者可查看；
- 返工照片仅管理员可查看，避免普通员工通过枚举 ID 查看；
- 所有图片路由在对象权限通过后，仍必须经过受管目录校验。

## 兼容与部署

- 不新增数据库表或字段；
- 部署前备份 PostgreSQL 和数据目录；
- 部署脚本在停服期间生成并安装 `ZY_SESSION_SECRET`，权限仅限 root/服务账号读取；
- 先盘点生产图片路径分布，再确定合法目录白名单；
- 上线后旧会话失效，用户重新登录即可，不修改账号密码；
- 若登录验证失败，可回滚代码并保留密钥；无数据迁移需要回滚。

## 测试

### 会话

- 登录返回的 Cookie 不再是纯数字；
- 合法签名 Cookie 可以访问对应角色页面；
- 修改用户 ID、时间或签名后不能登录；
- 旧纯数字 Cookie 不能登录；
- 过期 Cookie 不能登录；
- 停用用户即使持有旧签名也不能登录；
- 页面登录和 API 登录使用相同 Cookie 属性；
- 生产模式缺少密钥时启动失败。

### 图片路径与权限

- 合法受管图片和缩略图可以读取；
- 数据库中写入系统文件、上传目录外文件、`..` 路径或软链接逃逸时不能读取；
- 员工伪造 `existing_photo_path` 后，建议中不会保存伪造路径；
- 管理员伪造 `existing_photo_path` 后，正式作业信息不会保存伪造路径；
- 建议提交人和管理员能查看建议图片，其他员工不能查看；
- 普通员工不能查看返工图片；
- 原有发货照片和草稿照片所有权规则继续通过。

### 回归

- 完整测试套件通过；
- 页面登录、API 登录、退出登录、老板端和员工端入口通过；
- 员工作业信息建议上传、老板审核通过、共享作业信息查看完整走通。

## 实现边界

- 本次不实现多设备会话列表、单设备强制下线、短信验证或双因素认证；
- 不把图片迁移到对象存储或数据库；
- 不修复 SKU、条形码、同步脚本等其他审计项；这些按后续独立批次处理；
- 不为了兼容旧 Cookie 保留任何纯数字身份读取路径。
