# 员工发货记录补录照片和更新设计

日期：2026-08-04

## 目标

员工先上报发货数量，之后可以根据自己的已提交发货记录补录照片，也可以修正数量和备注。照片只能追加，不能由员工删除。员工提交更新后，由老板在现有审核页面确认。

## 范围

- 员工端“我的上报”显示每条上报记录的数量、备注、照片和更新入口。
- 员工只能更新自己提交的发货记录。
- 员工可以追加照片，但不能删除已有照片。
- 员工可以修改尺码数量和备注。
- 员工更新数量或备注后，记录状态改为 `pending_review`，等待老板审核。
- 员工只补录照片、不改数量和备注时，也记录为待审核，方便老板确认照片已经补齐。
- 老板端继续使用现有待审核和发货明细页面审核，不新增独立审核流。

## 数据保护

- 不删除现有数据库记录。
- 不删除现有照片文件。
- 照片补录使用现有图片校验和存储流程。
- 修改发货记录前，先备份本地数据；线上部署前，需要在腾讯云服务器对 PostgreSQL 数据库 `zy_shipping` 执行备份。

## 交互

员工打开“我的上报”后，每条记录下方有一个更新表单：

- 尺码和数量输入框预填当前上报内容。
- 备注输入框预填当前备注。
- 照片上传框支持多张图片。
- 按钮文案为“提交更新给老板审核”。

提交后返回“我的上报”，记录显示为待审核。

## 错误处理

- 未登录用户跳转登录页。
- 员工访问别人的记录时不允许修改。
- 图片格式不支持或内容不是有效图片时，返回提示，不保存部分更新。
- 数量为空、不是数字或小于等于 0 时，不保存更新。

## 测试

- 员工可以给自己的已提交记录追加照片。
- 员工追加照片后，原有照片仍保留。
- 员工不能更新别人的发货记录。
- 员工修改数量和备注后，记录进入待审核。
- “我的上报”页面显示更新表单，但不显示删除照片入口。
