# 登录页手机版/电脑版手动切换设计

## 目标

域名绑定后，用户打开网站默认进入电脑版登录页。员工在手机上需要使用手机版登录页。本设计在登录页增加“手机版 / 电脑版”手动切换入口，让用户在输入账号密码前自行选择版本。

只做登录页入口切换，不改变登录接口、账号角色分流、页面默认跳转逻辑，也不做设备自动识别或选择记忆。

## 现状

- 根路径 `/` 直接重定向到 `/app`，即 Vue 电脑版登录页（管理端登录，标题“ZY服装发货管理系统 / 管理端登录”）。
- 电脑版登录页由 `web/src/views/Login.vue` 渲染，登录走 `/api/v1/login`，成功后进入 Vue 管理端。
- 手机版登录页由 `app/templates/mobile/login.html` 渲染，地址为 `/mobile/login`（`/login` 也渲染同一模板），表单提交到 `/login`，登录后按角色进入 `/mobile` 或既有 `/admin` 页面。
- 两个登录页之间目前没有任何互切入口。

## 方案

方案 A：两个登录页互相增加版本切换入口，入口只做页面跳转。

### 电脑版登录页（Login.vue）

- 在登录卡片标题/副标题区域下方增加一行“手机版 / 电脑版”分段选择。
- “电脑版”为当前选中态（不可点击）。
- “手机版”链接到 `/mobile/login`，点击后进入手机版登录页。

### 手机版登录页（mobile/login.html）

- 在登录表单下方增加同样的一行“手机版 / 电脑版”分段选择。
- “手机版”为当前选中态（不可点击）。
- “电脑版”链接到 `/app`，点击后进入电脑版登录页。

### 样式与缓存

- Vue 页面样式写入 `Login.vue` 的 scoped style。
- 手机版页面样式写入 `app/static/app.css`，并同步更新模板中 `app.css` 的查询版本号（如 `?v=20260907-1`），避免手机浏览器继续使用旧缓存。
- Vue 构建产物自带内容哈希，无需额外缓存处理。

## 不做的事

- 不修改 `/` 的重定向逻辑。
- 不修改 `/login`、`/api/v1/login` 及登录后的角色跳转。
- 不增加设备识别或记住上次选择的本地存储。
- 不合并电脑版和手机版登录流程。

## 验证

1. 后端页面测试：`GET /mobile/login` 返回的 HTML 包含指向 `/app` 的“电脑版”入口。
2. 前端构建成功：`cd web && npm run build`。
3. 构建产物中能找到指向 `/mobile/login` 的“手机版”入口。
4. 部署到新服务器后，用浏览器实测两个登录页互相跳转正常。

## 部署

只更新新服务器（旧腾讯云服务器已过期，不再操作）：

1. 修改本地代码并跑通测试与构建。
2. 将 `app/templates/mobile/login.html`、`app/static/app.css` 及新构建的 `web/dist` 同步到新服务器 `/home/ubuntu/zy-shipping`。
3. 重启 `zy-shipping` 服务并验证页面。

## 回滚

本次只改登录页模板、样式与前端静态文件，不涉及数据库。回滚时将上述文件恢复为上一个版本并重启服务即可。
