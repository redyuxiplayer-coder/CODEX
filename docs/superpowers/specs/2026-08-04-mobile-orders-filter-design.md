# 补货查看页筛选优化设计

日期：2026-08-04

## 目标

优化员工手机端"补货查看"页的筛选体验：选完即筛、聚焦还差/超发、支持款式维度，减少整页刷新的重复点击。

## 现状问题

- 公司、货物两个下拉，选完必须点"查询"按钮才生效，手机上两步操作别扭。
- 已发完的订单和还差/超发混在同一列表，补货时看不清要补什么。
- 筛选只到产品（例如"裁判"），选完仍显示所有款式，不够精准。

## 设计

### A. 交互顺手

- 公司从下拉改为快捷标签：全部 / 各公司，点击立即过滤。
- 货物下拉选完自动提交过滤，去掉"查询"按钮。
- URL 参数保留选中状态，刷新/分享不丢失。

### B. 结果聚焦

- 新增状态切换：全部 / 只看还差 / 只看超发 / 只看已完成。
- 卡片视觉区分：还差橙色左边线，超发红色，已完成灰色弱化。

### C. 筛选更准

- 新增款式下拉，按 公司 + 产品 + 款式 过滤。
- 服务端组合过滤：company / product / style / status。

## 涉及改动

- `app/main.py`：`mobile_orders` 路由新增 `style`、`status` 参数与过滤逻辑。
- `app/templates/mobile/orders.html`：重构筛选区（标签 + 自动过滤 + 款式 + 状态切换）。
- `app/static/app.css`：标签、切换按钮、状态卡片样式。
- `tests/test_pages.py`：覆盖新参数过滤行为。

## 状态取值

- `all`：全部（默认）
- `need`：还差 > 0
- `over`：超发 > 0
- `done`：还差 = 0 且超发 = 0

## 验证

- 失败测试先行：路由支持 style/status 并正确过滤。
- 全量测试通过；浏览器实测筛选交互。
